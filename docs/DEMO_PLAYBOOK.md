# JesSee Demo Playbook

## The promise

**Show the work once. Leave with a playbook.**

The demo should feel like one continuous transformation, not a tour of extension features. Start with a real outcome, show a short piece of work, then reveal how JesSee turns it into something another person can use without replaying a video.

## The two-minute story

| Time | Do | Say | What the viewer should notice |
| --- | --- | --- | --- |
| 0:00 | Open the product page and JesSee. | “I need to explain this workflow without writing it all down.” | The next action is obvious and the setup is quiet. |
| 0:15 | Start capture and state the intended outcome. | “I’m going to show how a customer changes the image on this page.” | The recorder gives a simple three-part rhythm. |
| 0:30 | Perform three deliberate actions. Pause briefly after each result. | Explain intent and what changed, not every mouse movement. | The glowing pointer makes clicks clear without covering the product. |
| 0:55 | Stop on the finished state. | “That’s the result I want the next person to reproduce.” | The ending is visually unambiguous. |
| 1:05 | Create the plan. | “JesSee turns the walkthrough into an editable visual story.” | Outcome, takeaways, and sections are already organized. |
| 1:25 | Move through two sections and swap one image. | “It suggests the best evidence, but I choose what actually proves the step.” | The user stays in control of the image selection. |
| 1:50 | Generate the PDF. | “Now this can be reviewed or handed off without watching the recording.” | The artifact—not the recording—is the payoff. |

## Demo rules

- Use a clean demo account with no private customer data.
- Keep the capture to three actions and roughly one minute.
- Narrate the goal, the reason for each action, and the visible result.
- Pause for one beat after an important state change so JesSee has a strong evidence frame.
- Use highlight or redaction once only when it makes the story clearer.
- Preflight the microphone, API key, Safari permission, and PDF download before presenting.
- Keep one completed capture ready as a fallback, but begin with a fresh recording.

## UX bar

Every screen should answer one question:

1. **Before capture:** What should I do next?
2. **During capture:** Am I explaining this clearly?
3. **During review:** Which image best proves this piece?
4. **At the end:** Is this ready to hand to someone else?

If the demo needs a long explanation at any of those points, the product still has work to do.
